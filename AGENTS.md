# AGENTS.md

This file provides guidance to AI coding agents when working with code in this
repository.

Upptime status page for CCCP.PS: GitHub Actions run the checks, GitHub Issues are the
incident log, and the site is deployed from the `gh-pages` branch to https://up.cccp.ps.

## What you may edit

Hand-edited — this is the entire surface:

- `.upptimerc.yml` — monitors, site branding, theme/logo URLs
- `assets/**` — CSS, logos, favicons served by the status site
- `README.md`, but only outside the `<!--live status-->` line and the
  `<!--start: status pages-->` … `<!--end: status pages-->` block

Generated — edits get overwritten on the next CI run; change `.upptimerc.yml` instead:

- `.github/workflows/*.yml` — rewritten by Setup CI and Update Template CI (each carries a
  "Do not edit this file directly!" header); `.github/ISSUE_TEMPLATE/*` comes from the same
  upstream template
- `history/**` (check log + `summary.json`), `api/**` (shields.io badge JSON),
  `graphs/**` (PNG charts)
- the README status table, rewritten by Summary CI

`gh-pages` is a CI deploy target (published from `site/status-page/__sapper__/export/`).
Don't commit to it by hand.

## No local toolchain

There is no `package.json`, lockfile, build, test, or lint step — everything runs inside
`upptime/uptime-monitor` on GitHub Actions. Local checking is limited to
`yq . .upptimerc.yml` for syntax; real verification is the CI run
(`gh run list -R cccp-ps/uptime`).

## What triggers what

- push touching `.upptimerc.yml` → Setup CI: regenerates workflows and templates, rebuilds
  graphs and README, redeploys the site
- push touching `assets/**` → Static Site CI: rebuilds and deploys to `gh-pages`
- Uptime CI runs every 5 minutes and commits to `master`; Summary, Graphs, Response Time
  and Update Template CI run daily

Static Site CI is skipped when the head commit message contains `[skip ci]`
(`.github/workflows/site.yml`), so an asset change committed with `[skip ci]` silently
never reaches the live site. Setup CI has no such guard.

## Gotchas

- Monitored URLs are secrets. `.upptimerc.yml` uses `url: $SECRET_SITE_001`, resolved from
  the repo secret of that name, and `history/*.yml` stores the placeholder rather than the
  URL — never inline a real URL. To add a monitor: create `SECRET_SITE_00N` in repo
  settings and reference `$SECRET_SITE_00N` in `.upptimerc.yml`. The `SECRETS_CONTEXT`
  allowlist inside the generated workflows is derived from `.upptimerc.yml`; don't edit it
  there.
- `assets/*` is served from the site root — `assets/custom-theme.css` becomes
  `https://up.cccp.ps/custom-theme.css`. `.upptimerc.yml` points at those files by absolute
  URL (`themeUrl`, `logoUrl`, `faviconSvg`), so a new asset needs both the file and a
  matching `https://up.cccp.ps/<name>` reference, and it only resolves once the site has
  deployed. There is no local preview of the status site.
- JetBrains Mono is loaded in two places: `status-website.links` in `.upptimerc.yml` and
  the `@import` at the top of `assets/custom-theme.css`. Change both.
- The response-time graph PNGs are generated green upstream; the dark theme recolors them
  with a `hue-rotate` filter on `article.graph::before` in `assets/custom-theme.css` (and
  `--graph-filter`). Changing the status palette means changing that filter too.
- Upptime version pins (`upptime/uptime-monitor@v1.43.15`) are bumped by Update Template CI
  in `:arrow_up:` commits — don't bump them by hand.
- `master` receives bot commits every ~5 minutes. `git pull --rebase` before pushing, and
  don't force-push: it rewrites the monitoring dataset in `history/`.

## Commits

Human commits use Conventional Commits (`feat:`, `fix:`, `style:`, `chore:`, `docs:`). The
emoji prefixes with `[skip ci]` (`🟩`/`🟥`, `:bento:`, `:card_file_box:`, `:pencil:`,
`:arrow_up:`) belong to the bots — don't imitate them.
